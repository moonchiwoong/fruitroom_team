# 애플트랙 AI 도우미 운영 안내

## 현재 상태

읽기 전용 MCP 서버·클라이언트, 고객용 API, 공급자 어댑터와 영속 요청 한도 SQL을 구현했습니다. **실제 AI 공급자·키·모델·단가를 연결하지 않았고 운영 Supabase에 SQL을 적용하지 않았습니다. 실제 고객 계정의 RLS, 실제 모델 응답·비용, 운영 배포는 검증하지 않았습니다.** 설정이 없거나 한도 확인에 실패하면 AI 설명은 비활성화됩니다. 기존 물량·품질 화면은 계속 사용할 수 있습니다.

소스 출처는 제공 GitHub 원본 commit `08ac94953e9916c7af6c0e1b70e7b4de8a6c91df`와 업로드 ZIP이 일치하는 것으로 확인했습니다. 실제 운영 사이트의 배포 소스 연결은 미확인입니다. 이 문서의 구현·검증 결과가 운영 배포 완료를 뜻하지 않습니다.

## 동작과 데이터 경계

- `POST /api/ai/chat`: 세션 인증 → 요청/범위 검증 → Supabase 원자적 비용 예약 → 실제 MCP SDK Client/Server 연결 → 허용된 조회 도구 → 공급자 설명 코드 선택 → 권한 재확인 → 서버 문구·근거 반환.
- 서버 내부 연결은 `@modelcontextprotocol/sdk@1.25.2`의 `Client`, `McpServer`, `InMemoryTransport`를 사용합니다. 임의 함수 호출을 MCP로 표기한 구조가 아닙니다. 각 요청에 새 연결을 만들고 종료합니다.
- `POST /api/ai/mcp`: SDK Streamable HTTP 서버도 제공합니다. 기존 로그인 쿠키를 사용하는 자사 앱용이며 공개 OAuth MCP 서비스가 아닙니다. 요청별 독립 처리이고 재연결 세션/이벤트 기록을 저장하지 않습니다. GET/DELETE는 405입니다.
- 외부 AI는 도구나 DB를 직접 호출하지 않습니다. 서버가 질문·선택 범위에 따라 읽기 도구를 고정된 상한 안에서 호출하고, AI는 허용된 설명 항목 코드만 선택합니다. 수치·날짜·최종 문장은 기존 계산 결과와 서버에서 검증한 문구를 사용합니다. 자유 생성 텍스트·새 계산·출하 권고는 응답에 삽입하지 않습니다.
- 모든 도구 호출에서 현재 인증을 다시 확인하고, DB의 기존 RLS와 별도로 `owner_id` 또는 현재 팀 공유 권한을 검사합니다. 고객 식별자는 요청 인자로 받지 않습니다. 선택 물량을 다른 물량 ID로 바꾸는 호출은 거절합니다.
- 기존 `getLot`, `getAnalysis`, `listLots`와 사용자 세션의 Supabase 클라이언트를 재사용합니다. 서비스 역할 키를 사용하지 않습니다. 물량 생성·수정·삭제·공유 변경 도구는 없습니다.
- 선택 예측 화면의 값은 `computeSeries`, `valueAt`, `measuredPoints`, `describeChange`와 공통 품질 정책을 재사용합니다. 실측 기록의 초기값은 DB에서 읽고, 저장 물량의 입력을 바꾼 계산은 미저장 시뮬레이션으로 표시합니다.
- 실제 감모율은 동일 추적 표본 식별자와 초기·후속 중량·측정일이 확인된 측정 날짜에만 표시합니다. 모델 감모율을 실제 기록으로 반환하지 않습니다. 초기 측정일이 분석 기준일 이후면 계산하지 않습니다.
- 기준 비교는 초기값·저장 조건·측정 조건·분석 기준일·측정 이력을 대조합니다. 이력 fingerprint는 브라우저와 서버의 재현 비교용이며 인증 수단이 아닙니다.
- 같은 날짜 실측/계산을 비교합니다. 명시적으로 다른 측정 조건은 차이 비교를 막고, 조건 미기록은 확인 필요로 표시합니다. 저장 초기값→최근 실측 변화는 실제 날짜가 있는 같은 지표에만 표시합니다.
- 물량 화면 질문에서 예측 지표·날짜를 임의로 추정하지 않습니다. 품질 예측 화면에서 지표와 날짜를 선택하도록 안내합니다. HTTP MCP의 계산 도구도 해당 예측 화면 맥락이 없으면 이를 설명하며 거절합니다.

### 읽기 전용 도구

| 도구 | 범위 |
| --- | --- |
| `list_accessible_lots` | 권한 내 물량 목록, 최대 기존 조회 한도 100개 |
| `get_lot_details` | 선택 물량·저장 조건 |
| `get_quality_measurements` | 저장 초기값, 지표별 최근 실측, 최근 후속 기록 최대 30개 |
| `get_environment_history_summary` | 온습도 이력 요약, 계산 미반영 상태 |
| `run_existing_quality_prediction` | 선택 예측 맥락의 기존 엔진 결과 |
| `compare_measurement_with_prediction` | 실측과 같은 날짜의 계산 비교 |
| `get_model_information` | 모델 버전, 미검증 적용 범위·제약 |

전체 물량 질문의 상세 측정 조회는 최근 등록 물량 최대 3개로 제한하고 일부 조회임을 표시합니다. DB 관측 조회 한도에 닿거나 반환 기록이 일부인 경우 전체 이력으로 설명하지 않습니다. 예시/미저장 입력은 실제 물량 목록을 조회하지 않습니다.

## 필요한 운영 설정

다음 값은 **서버 환경 변수**입니다. `NEXT_PUBLIC_` 이름으로 만들거나 브라우저 코드에 넣지 마세요. 공급자나 모델의 기본값은 제공하지 않습니다.

| 변수 | 운영자가 설정할 값 |
| --- | --- |
| `AI_ENABLED` | 연결 검증 후 `true` |
| `AI_PROTOCOL` | `openai-compatible` |
| `AI_API_URL` | 승인한 공급자의 전체 HTTPS Chat Completions 호환 URL |
| `AI_API_KEY` | 해당 공급자의 서버 전용 비밀키 |
| `AI_MODEL` | 승인한 모델의 정확한 ID |
| `AI_INPUT_PRICE_PER_MILLION_USD` | 해당 모델 입력 백만 토큰당 USD 단가, 양수 |
| `AI_OUTPUT_PRICE_PER_MILLION_USD` | 해당 모델 출력 백만 토큰당 USD 단가, 양수 |

어댑터는 Chat Completions 호환 `messages`, `max_tokens`, `response_format:{type:'json_object'}` 요청과 `choices[0].message.content` JSON을 기대합니다. 이 형식을 지원하는 모델인지 실제 공급자에서 검증해야 합니다. 별도의 이미지·검색·도구 사용 비용이나 모델 고유 추론 요금이 붙는 모델에는 이 예약식을 그대로 적용하지 마세요. 실제 사용 모델의 청구 규칙과 최대 출력 제한 적용을 확인해야 합니다. 공급자의 모델·가격 변경 시 설정과 검증도 갱신해야 합니다.

API URL은 사용자 입력에서 받지 않고 운영 설정으로만 읽습니다. HTTPS 및 기본 주소 검사를 수행하고 리다이렉트하지 않습니다. 최종 접속 대상과 공급자 데이터 보존/국외 전송 정책은 운영자가 승인해야 합니다. 무료 또는 정확한 청구 상한을 검증하지 않은 모델에 임의 단가를 넣어 활성화하지 마세요.

### Supabase 마이그레이션과 활성화

1. 기존 DB를 백업하고 테스트 프로젝트에서 `supabase/2026-10-23_ai_budget.sql`을 관리자 SQL Editor로 적용합니다. 이 파일은 기존 물량/관측 테이블이나 기존 RLS를 수정하지 않습니다.
2. 새 `ai_limits`, `ai_budget_reservations`, `ai_read_windows` 테이블과 세 개의 RPC가 만들어집니다. 기본값은 AI 비활성화·월 한도 0입니다. 고객 역할은 테이블을 직접 읽거나 변경할 수 없습니다.
3. 관리자만 `ai_limits` 한 행의 승인된 `monthly_budget_usd`, `max_request_usd`, `per_user_daily`, `per_user_minute`, `mcp_per_user_minute`를 설정합니다. 고객 입력의 상한을 사용하지 않습니다. 1회 한도는 아래 예약액 이상이어야 정상 요청이 가능합니다.
4. 공급자 연동과 권한 분리·공유 취소를 테스트 계정으로 검증한 뒤 관리자 한도 행의 `enabled=true`와 서버 `AI_ENABLED=true`를 설정합니다. 설정되지 않거나 RPC 오류가 나면 요청은 차단됩니다.

예약액은 최대 요청 32,000 UTF-8 바이트 + 2,048 토큰 여유, 최대 출력 800 토큰에 운영자가 설정한 단가를 적용하고 마이크로달러 단위로 올림한 보수적 값입니다. 입력 바이트를 텍스트 토큰의 상한으로 취급하므로 실제 청구보다 큰 예약이 생길 수 있습니다. 이 계산은 승인한 공급자의 토큰화·청구 규칙 확인을 전제로 합니다. 예약 총액이 월 한도 안에 있을 때만 공급자를 호출합니다.

`reserve_ai_budget`는 보호된 설정 행을 잠가 서로 다른 서버 인스턴스의 동시 요청도 직렬화하고, 현재 `auth.uid()`의 분/일 요청 수 및 전체 UTC 월간 예약액을 검사합니다. 중복 요청 ID는 거절합니다. 실패·취소 요청도 예약을 환불하지 않으므로 재시도에 새 요청 ID가 필요합니다. 실제 청구보다 적게 반영되는 정산 경로는 만들지 않았습니다.

HTTP MCP에는 별도 DB 분당 읽기 한도를 적용합니다. 프로세스 내 사용자별 동시 요청 제한은 보조 방어이며 비용 한도를 대신하지 않습니다. 인증 사용자가 예약 RPC를 직접 호출해 자기 요청 한도 안에서 예약 예산을 소진할 수 있는 제한이 있습니다. 이는 외부 AI 호출을 발생시키지는 않지만 공유 한도 가용성에 영향을 줄 수 있으므로 운영 모니터링이 필요합니다.

### 비활성화·복구

즉시 중단하려면 서버 `AI_ENABLED`를 `false`로 바꾸고 관리자 SQL에서 `update public.ai_limits set enabled=false where singleton;`를 실행합니다. 기존 물량/품질 기능은 영향을 받지 않습니다.

마이그레이션 철회가 필요하면 AI 경로가 비활성화된 것을 확인한 뒤 새 예산 테이블을 별도로 백업합니다. 관리자 권한으로 다음 순서로 제거할 수 있습니다. 기존 고객 데이터 테이블은 삭제하지 않습니다.

```sql
begin;
drop function if exists public.consume_ai_read_quota();
drop function if exists public.reserve_ai_budget(uuid,numeric);
drop function if exists public.ai_budget_status();
drop table if exists public.ai_read_windows;
drop table if exists public.ai_budget_reservations;
drop table if exists public.ai_limits;
commit;
```

재적용하면 월간 예약 기록이 초기화되므로 같은 월에 재활성화할 때 이전 예약·청구액을 먼저 정산하고 한도에 반영해야 합니다.

## 보존·실패 처리

- 대화는 열린 화면의 메모리에만 보관하며 AI API가 대화 본문을 DB에 저장하지 않습니다. 새로고침/닫기 후 복원하지 않습니다. 기존 품질 입력 초안 저장은 별개입니다.
- 예산 기록에는 요청 UUID, 사용자 UUID, 예약 USD, 생성 시각만 보관합니다. 프롬프트·답변·물량 본문을 기록하지 않습니다. 월 정산 후 90일보다 오래된 예약 기록을 관리자가 정리할 수 있습니다. 현재 월의 행은 한도 계산에 쓰므로 삭제하면 안 됩니다. 읽기 한도 창은 2일 이전 행을 정리할 수 있습니다.
- 공급자에게 질문과 최소화한 서버 근거·표시값·해석 한계만 전달합니다. 고객/물량 ID, API 키, 원본 메모, 물량명, 원본 관측/센서 행, 사진은 프롬프트에 포함하지 않습니다. 사용자가 질문 자체에 직접 적은 정보는 전달됩니다. 공급자 측 보존 정책은 별도이며 이 구현이 공급자의 무보존을 보장하지 않습니다.
- 질문 최대 2,000자, 요청 48KiB, 공급자 입력 32,000바이트, 공급자 응답 64,000바이트, 채팅 전체 35초, 도구 호출 최대 8개/각 10초를 제한합니다. SDK/공급자 호출에 취소 신호를 전달합니다. 이미 실행 중인 기존 Supabase 조회는 즉시 중단을 보장하지 않지만 결과 반환 전 취소·권한을 다시 검사합니다. 취소된 외부 요청도 공급자가 과금할 수 있습니다.
- 인증 실패 401, 범위/교차 사이트 요청 오류 403 또는 일반화된 조회 불가, 요청 상한 413, 요청/예산 한도 429, 설정/외부 공급자 오류 503, 잘못된 공급자 응답 502를 사용합니다. 권한 없음과 존재하지 않는 물량을 동일하게 처리합니다. 상태/API 응답과 HTTP MCP 결과는 `private, no-store`입니다.

## 검증과 남은 확인

`node --import tsx --test tests/ai-mcp.test.ts`는 가짜 사용자·가짜 물량 어댑터로 실제 MCP SDK 왕복, 읽기 도구 목록, 권한/공유/범위 격리, 예시/초안 분리, 취소/도구 제한, 계산 엔진 일치, 날짜/감모/측정조건 정책, 코드 allowlist, 미설정 차단과 데이터 최소화를 검사합니다. SDK Streamable HTTP Client의 initialize/list/call도 in-process fetch로 실제 프로토콜을 왕복합니다. 실제 네트워크 또는 운영 계정의 인증 검증으로 표기하지 않습니다.

SQL은 별도 격리 PGlite/PostgreSQL fixture에서 18개 검증을 통과했습니다. 재현 방법과 제한은 [SQL 검증 기록](../tests/ai-budget-sql.md), 테스트는 `tests/ai-budget-sql.test.mjs`를 확인하세요. 실제 Supabase SQL 적용·운영 DB RLS 검증과는 구분합니다.

출시 전에는 운영자가 테스트 계정 A/B/팀 공유를 사용해 개인 물량 격리, 공유 철회, 로그아웃 중 요청, 실제 공급자 형식/응답/단가, 동시 예산 소진, 재시도·취소, 데이터 보존, 실제 배포 환경 연결을 확인해야 합니다. 이 확인이 끝나기 전에는 운영 AI 연결 완료로 표시하지 않습니다.
