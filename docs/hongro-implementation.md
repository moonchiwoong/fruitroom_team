# 홍로·거창 구현과 검증

## 구현 범위

품질 예측 화면의 `홍로 · 거창`을 선택하면 전용 계산기가 열립니다. 기존 후지 화면, 회귀 계수, 저장식을 보존했습니다. 기존 로그인과 기록 권한, 측정 기록·초안·내보내기·3D 경로를 삭제하지 않았습니다.

- 초기품질: 직접 측정값 또는 기상변수 4개로 계산한 회귀 추정값을 구분합니다. 첨부 이미지의 5개 회귀식과 R²를 그대로 전사했으며 합성자료로 계수를 다시 학습하지 않았습니다.
- 저장조건: 0℃/4℃ 저온저장, 0~120일. 숫자 입력·슬라이더·서버의 공용 계산 함수가 같은 범위를 검증합니다. 누락값은 0으로 바꾸지 않습니다.
- 경도·산도·당도: 최종값과 초기 대비 변화량, 각각의 단위가 있는 그래프, 동일 초기값의 두 온도 비교를 제공합니다. 산도 변화량은 %p입니다.
- 중량·횡경: 초기값만 제공합니다. 감모율·중량·횡경의 저장 변화와 홍로 3D 품질 변화를 새로 추정하지 않습니다.
- 홍로 입력: 사용자별 브라우저 초안과 CSV 내보내기를 제공합니다. 홍로 계산 결과를 Supabase 정식 물량·측정 기록에 자동 저장하지 않습니다. 기존 물량·측정 기록 기능은 유지합니다.
- 기존 모델 보호: 자유 입력 품종이 홍로/Hongro이면 후지 계산, 기존 연결 확인용 예측, 해당 AI 예측을 거절합니다. 서버는 클라이언트 품종뿐 아니라 권한 확인 후 읽은 실제 물량의 품종도 검사합니다. 과거 홍로의 부적합한 계산값은 응답에서 가리고 저장 원본은 유지합니다.

## 수식·출처

[원문 계수·자료 해시·PDF 측정법·남은 확인 사항](hongro-sources.md)에 기록했습니다. 계산은 `lib/hongro.ts`에 모으고 기존 후지의 `lib/initial-quality.ts` 계수를 변경하지 않습니다.

`F0=68 N`, `A0=0.18%`, `S0=14.2 °Brix`라는 검증용 입력의 예상 결과입니다. 실제 농가 측정값이 아닙니다.

| 일수 | 0℃ 경도 N | 4℃ 경도 N | 0℃ 산도 % | 4℃ 산도 % | 당도 °Brix |
| --- | ---: | ---: | ---: | ---: | ---: |
| 0 | 68 | 68 | 0.18 | 0.18 | 14.2 |
| 60 | 61 | 61 | 0.18 | 0.18 | 14.2 |
| 120 | 53.6 | 52.4 | 0.13 | 0.15 | 14.2 |

당도식은 `S(t)=S0`입니다. 모델에서 저장 중 당도 변화를 반영하지 않음으로 표시하며, 실제 과실의 당도가 일정하다고 해석하지 않습니다. 120일은 계산 적용 범위이고 안전한 저장 기간이나 판매 가능 기간을 보증하지 않습니다.

## 계산 API

`GET /api/predictions/hongro`는 모델 버전과 입력 명세를 반환합니다. `POST`는 다음과 같은 JSON을 받습니다. 계정·물량 데이터를 읽거나 쓰지 않는 독립 계산 API이며, 기존 인증·물량 API의 권한을 변경하지 않습니다.

```json
{
  "cultivar": "hongro",
  "region": "geochang",
  "source": "measured",
  "storage": "cold0",
  "days": 120,
  "initial": {"firmness": 68, "brix": 14.2, "acidity": 0.18}
}
```

기상 입력은 `source: "weather"`와 `weather: {chang_min4, chang_LC56, chang_LC78, chang_9rain}`을 사용하고 `initial`을 함께 보내지 않습니다. 모든 수치는 JSON 숫자여야 하며 문자열·null·누락·잘못된 품종/지역/조건·0~120일 밖 요청은 400 오류를 반환합니다. 회귀 결과가 음수이거나 유한하지 않으면 계수 변경·0 보정 없이 계산을 중단합니다. 합성자료의 입력 범위 밖은 경고하되 검증된 생육 한계로 취급하지 않습니다.

## 확인 필요 사항

- 계수 이미지의 `N/mm`와 사용자·PDF의 `N(직경 11 mm 탐침)` 표기가 충돌합니다. 사용자 지정 기준으로 수치를 변환하지 않고 계산하며 초기 회귀자료와 저장실험의 측정 기준 동일성은 아직 확인되지 않았습니다.
- 초기 회귀의 출처는 HWPX 화면 이미지이며 원본 HWPX 파일을 직접 열었다고 표시하지 않습니다.
- 합성자료의 회귀식과 별개 문헌의 저장 변화를 결합한 모델로, 실제 농가·과실에 대한 독립 예측 성능 검증은 완료되지 않았습니다. R²는 정확도나 신뢰확률이 아닙니다.
- 홍로 결과의 AI 설명과 Supabase 정식 예측 이력 저장은 이번 전용 계산기에 연결하지 않았습니다. 기존 AI 공급자·예산 설정 상태는 별도로 확인해야 합니다.

## 검증 상태

단위 테스트 56개와 브라우저 테스트 47개(기존 화면 35개 + 홍로 전용 12개)가 모두 통과했습니다. `npm run typecheck`도 오류 없이 완료됐습니다. `npm run build`는 컴파일·TypeScript 검사·정적 페이지 8개 생성·페이지 최적화를 마쳤으며, 최종 경로 목록에 `/api/predictions/hongro`가 포함됐습니다.

홍로 브라우저 검증에서는 빈값·누락값 차단, 실측 초기값과 0/60/120일의 0℃·4℃ 결과, 범위 밖 입력 차단, 기상 4변수 회귀, 음수 회귀 결과 차단, 세 지표 그래프와 단위, 초기 중량·횡경 표시, 사용자별 초안 복구·분리, 전용 CSV 메타데이터, 데스크톱 1440px·모바일 390px 화면을 확인했습니다. 홍로 검사에서 JavaScript pageerror는 0개였습니다.

브라우저 검증은 가상 Supabase 인증·프로필·물량 응답을 사용한 로컬 fixture 검증입니다. 실제 고객 기록을 사용하거나 변경하지 않았으며, 실서비스 로그인·실DB 권한/RLS·실제 저장 성공은 검증하지 않았습니다. 데스크톱·모바일 화면도 검증용 입력으로 촬영한 로컬 화면입니다.

빌드된 앱을 `next start`로 실행한 로컬 프로덕션 HTTP 검사 11개도 통과했습니다. Origin 헤더 없는 API 클라이언트로 모델 명세 GET 1개, 실측 초기값의 0/60/120일·0℃/4℃ POST 6개, 잘못된 일수(-1·121)·CA 조건·산도 누락의 400 거절 4개를 확인했습니다. 계정·DB에 접근하지 않았으며 검사 서버는 종료했습니다.

개발 검증 시 `127.0.0.1`과 `localhost`의 Origin 별칭 차이로 403이 발생할 수 있으며, 운영 사이트 Origin을 포함한 POST 동작은 아직 검증하지 않았습니다.

실제 배포는 아직 커밋 대기 상태입니다. 로컬 타입 검사·테스트·프로덕션 빌드 성공을 운영 사이트 배포 완료로 표시하지 않습니다.
