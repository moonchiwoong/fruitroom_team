## 2. UI 개편

상단을 홈 / 품질 예측 / 물량 관리로 정리하고 내 정보는 별도 계정 메뉴에 유지했습니다. 홈은 소개·실측 입력·예시 체험과 최근 물량으로 구성했습니다.

첫 입력은 입력·단계 안내를 우선, 기존 물량은 결과·그래프를 우선 보여줍니다. 단일 지표 탭, 그래프 바로 아래 날짜·슬라이더, 같은 날짜 최근 실측 비교, 접힌 조건 비교를 연결했습니다. 모델 정보는 결과·푸터·기존 `#model` 주소로 접근하며 3D는 하단에 접혀 있습니다.

물량 관리에는 이름·품종·위치 검색, 데스크톱 목록/상세, 모바일 목록↔상세, 품질/온습도/사진 탭을 적용했습니다. 기록 입력·사진·환경 CSV 경로를 보존했습니다.

## 3. AI 구현과 연결 상태

홈, 예측 결과, 물량 상세의 세 진입점이 같은 AI 도우미로 연결됩니다. 선택 범위·지표·날짜·초안·고정 기준을 전달하고 범위 변경/닫기/계정 변경 시 대화를 폐기합니다. 취소·재시도와 늦은 응답 격리를 구현했습니다.

실제 MCP SDK Client/Server와 Streamable HTTP 경로, 읽기 전용 도구 7개를 구현했습니다. `list_accessible_lots`, `get_lot_details`, `get_quality_measurements`, `get_environment_history_summary`, `run_existing_quality_prediction`, `compare_measurement_with_prediction`, `get_model_information`입니다. 기존 사용자 세션·RLS 조회 함수와 계산 엔진을 재사용합니다.

MCP 프로토콜 왕복은 테스트 어댑터로 검증했습니다. **운영 DB·실제 AI 공급자·모델·API 키·과금 연결은 미검증**입니다. 현재 설정이 없어 AI는 사용 불가 안내를 표시합니다. 운영 연결 없이 모의 답변을 실제 답변으로 제공하지 않습니다.

모델은 허용된 근거 설명 코드만 선택합니다. 수치·날짜·차이·최종 문장은 서버가 생성하므로 별도 예측식이나 근거 없는 출하·안전 권고를 자유 생성하지 않습니다. 원본 메모·사진·고객 ID를 공급자에게 전달하지 않습니다. 상세 설정과 최소 데이터 전달 범위는 [AI 운영 안내](ai-operations.md)에 기록했습니다.

## 5. 보존과 보완

- 로그인, 개인/팀 공유의 기존 조회·저장 경로와 RLS SQL을 보존했습니다. 실제 배포 정책의 동작은 별도 검증해야 합니다. 계정 전환 시 이전 사용자 화면 상태를 재마운트합니다.
- 초기/후속 측정·사진·환경 CSV·초안·기준 고정·내보내기·3D 경로를 유지했습니다. UI 테스트에서는 실제 저장 요청을 운영 서버로 보내지 않았습니다.
- 모델 식·계수는 바꾸지 않았습니다. 동일 입력에 대한 3개 조건×3개 지표×3개 시점의 계산 값이 원본과 일치했습니다.
- 실제 감모율은 동일 추적 표본 ID·초기/후속 중량·날짜가 있어야 출력합니다. 표본 ID가 없는 과거 기록을 임의로 연결하지 않습니다. JSON 상세 필드에 추가하여 기존 테이블 마이그레이션이 필요하지 않습니다.
- N↔kgf는 표시 환산이며 N 원본을 보존합니다. 탐침 직경만으로 kgf/cm² 수치를 제공하지 않습니다. 공통 정책·MCP·내보내기에도 제한을 적용했습니다.
- 분석 기준일 뒤의 초기 실측을 계산에 사용하지 않습니다. 명시적 측정 조건 불일치는 실측/계산 차이 비교를 막고 조건 미기록은 확인 필요로 표시합니다.
- CSV 반올림을 UI와 통일하고 물량명 같은 자유 텍스트가 스프레드시트 수식으로 실행되지 않도록 처리했습니다.
- 새 서버 변경은 AI API·MCP·어댑터 및 `supabase/2026-10-23_ai_budget.sql`입니다. 예산/읽기 한도용 새 테이블 3개·RPC 3개만 추가하며 기본은 비활성화입니다. 운영 적용은 하지 않았습니다.

## 6. 필요한 설정과 미해결 사항

AI 공급자·모델, 서버 전용 `AI_API_URL`·`AI_API_KEY`·`AI_MODEL`·`AI_PROTOCOL`, `AI_ENABLED`, 입력/출력 단가, 승인된 월간/요청당/사용자별 한도 설정이 필요합니다. SQL은 스테이징에서 확인한 뒤 적용하고 실제 공급자 형식·청구 규칙을 검증해야 합니다. 키를 소스나 브라우저에 넣지 않습니다.

대화 본문은 서버에 저장하지 않으며 패널 닫기·조회 범위 변경·새로고침·계정 변경 시 폐기합니다. 공급자의 별도 보존 정책은 확인이 필요합니다. 예산 기록은 대화 내용 없이 요청/사용자 ID·금액·시간만 보관하며 90일 이후 정리 절차가 문서에 있습니다.

모델의 검증된 적용 기간·오차 범위·측정법 근거는 여전히 미확인입니다. 품종 보정·실측 온습도·사진은 현재 저장 수식에 반영되지 않습니다. 저장 허용 숫자 범위를 과학적 정상 범위로 바꾸지 않았고 출하일·보관 기간·안전·신선도 등급을 판정하지 않습니다.

운영 반영에는 해당 Netlify 프로젝트의 연결 저장소·브랜치·배포 커밋 확인 및 접근 권한이 필요합니다. 이 소스 ZIP은 정적 사이트 배포 파일이 아닙니다. 기존 저장소에서 검토 후 Next.js 빌드 절차로 반영해야 합니다.

## 7. 실제 구현 화면

별도 제공한 `appletrack-review.html`에 홈·품질 예측·물량 상세·AI 미설정·3D·모바일 화면을 포함했습니다. 실제 구현을 브라우저로 촬영한 것으로 디자인 목업이 아닙니다. 단, 화면의 `[검증 예시]` 물량과 기록은 테스트용 가상 데이터이며 운영 데이터가 아닙니다.
